# Архитектурное Видение Users Service

## Назначение

`users_service` — bounded context для профилей пользователей, ролей и связей родитель-ученик.
Сервис обслуживает админов, преподавателей, родителей и учеников через явные доменные политики и правила жизненного цикла.

Ключевые цели:
- централизовать владение пользовательским доменом
- держать инварианты ролей и связей в одном месте
- предоставить стабильные контракты для сервисов платформы
- сохранить чистые границы с auth и course контекстами

## Бизнес-ценность

Сервис обеспечивает:
- единый источник истины по пользователям платформы
- явную ролевую модель (`admin`, `teacher`, `parent`, `student`)
- надежные связи parent-student для образовательных сценариев
- аудируемые переходы жизненного цикла (`active/blocked/archived`)

## Границы

### Входит в контекст
- `UserProfile`
- `RoleAssignment`
- `ParentStudentLink`
- `UserStatus`
- lifecycle-операции над пользователями и audit events

### Не входит в контекст
- login/password/JWT/JWKS lifecycle (`auth_service`)
- контент курсов и учебная доставка (`course_service`)
- orchestration уведомлений
- UI/BFF orchestration

## Принципы

- Domain first и управление через инварианты
- Явные policy-based проверки доступа
- Интеграции только через порты
- Без общей БД с внешними сервисами
- Контракты версионируются и тестируются
